# BRAINK Encoded-Medium Storage Architecture — Authoritative Reconciliation v1

## Authoritative primitive

`Encoded Script Runtime Structure = Software-Defined Storage Medium`

The source text is the authoring/manufacturing representation. Source-line identifiers are provenance only. They are not storage addresses.

## Canonical hierarchy

`EncodedScript -> SoftwareStorageMedium -> ZerolessMatrixAddressGeometry -> BRAINK/KEXStorageController -> VirtualBlock/ObjectSpace -> VFSInterpretation -> LogicalObjects`

Machine boot invariant:

`BRAINKRoot_i ∈ EncodedMedium_i`

BRAINK is therefore decoded from the already-encoded medium rather than attached after the machine is assembled.

## Typed roles

- `L#`: source provenance.
- Matrix/vector coordinates: encoded address geometry.
- Adapter/controller: translation, allocation, read/write, reconstruction, lineage and integrity.
- Logical block/object space: decoded controller-level objects.
- VFS: filesystem/resolver interpretation over logical objects.
- Sheets/workbook rows: observer/readback projection where used.
- Network/IP/HTTP: carrier projection, not foundational BRAINK identity.
- Registry: instrumentation/proof unless separately demonstrated to be an encoded-medium primitive.

## Rejected hierarchy

`SourceLine -> Volume -> VFS -> BRAINK`

This interpretation is superseded.

## Re-parenting of prior work

- `volume registry` -> observation/proof registry.
- `L#` -> source provenance.
- `sheet rows` -> projection/readback.
- `VFS` -> filesystem/resolver utility.
- `100 TB rows` -> projection of encoded address law.
- nine `L19-L27` logical volumes -> instrumented logical address-space instances, not proof of the fundamental storage primitive.
- `9 x 100 TB = 900 TB` -> valid result for the utility-created isolated address spaces, not proof that the actual BRAINK encoded medium had been reconstructed.
- `IP -> endpoint -> BRAINK` -> reversed; BRAINK identity/address fabric resolves through adapters to IP/HTTP carrier projections.

## Evidence retention rule

Existing evidence is retained when the observed property survives the corrected parentage. Architectural claims are demoted or rejected when they depended on the superseded `line -> volume -> VFS` interpretation.

## Authoritative machine model

`M_i = (EncodedMedium_i, Controller_i, BRAINKRoot_i, Compute_i, Memory_i, GPU_i, Network_i, Observer_i, Proof_i)`

with `BRAINKRoot_i ∈ EncodedMedium_i`.
