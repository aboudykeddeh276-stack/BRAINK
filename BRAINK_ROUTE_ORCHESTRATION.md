# BRAINK route orchestration

The native workflow drives the existing BRAINK routes directly through `BRAINKChatEngine`.

## Route map

| Prompt class | Route | Output |
| --- | --- | --- |
| `knowledge center status` | `knowledge_center_status` | IL-LLM runtime status and memory snapshot |
| `proof packet` | `proof_packet` | Local proof packet JSON when external proof tooling is unavailable |
| transition / definition / state language | `kex_hyperdrive` | `NativeChatBot/build/kex_hyperdrive_repo_calibration_report.json` |
| self-sustained coding language | `self_sustained_coder` | `NativeChatBot/build/kex_self_sustained_coding_report.json` |
| stack audit language | `stack_audit` | `NativeChatBot/build/braink_stack_alignment_report.json` and `NativeChatBot/build/braink_module_alignment_audit.json` |

## Orchestration flow

1. Start in `bridged` mode when `BRAINK_API_ENDPOINT` is configured; otherwise run deterministic local mode.
2. Execute the primary route sequence and persist `braink_primary_orchestration_summary.json`.
3. Execute a fallback probe against an unreachable local endpoint to confirm `system.fallback` behavior and persist `braink_fallback_orchestration_summary.json`.
4. Combine route outputs, proof packet content, and artifact hashes into `NativeChatBot/build/braink_delivery_evidence.json`.

## Proof and audit artifacts

- `braink_delivery_evidence.json` — consolidated proof packet, fallback probe, and SHA-256 artifact hashes
- `braink_module_alignment_audit.json` — workflow-friendly alias of the stack audit output
- `braink_stack_alignment_report.json` — native alignment report generated by `BRAINKDeliveryAudit`
- `kex_hyperdrive_repo_calibration_report.json` — repo calibration and alignment status
- `kex_self_sustained_coding_report.json` — bounded self-sustained coding task packets
