## Runtime principle

Every repository is parsed as software-thought before it is changed. The repository is not treated as a disposable code folder. It is treated as a state-bearing engineering sector that can be inspected, aligned, projected, and improved through additive proof artifacts.

## Mathematical efficiency rule

Technology progresses by measurable efficiency. Every sector must prefer:

1. lower overhead,
2. lower duplication,
3. faster boot comprehension,
4. stronger reuse of existing working code,
5. deterministic verification where possible,
6. additive repair memory over isolated rewrites.

A low intake sector is still useful when it is mathematically clean. Even a 20 percent intake sector can contribute if its state, proof, and purpose are preserved.
